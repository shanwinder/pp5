# กติกาถาวรการทำงานของตารางคะแนน PP5 (Gradebook Interaction Lock)

**ประกาศใช้อ้างอิง:** 10 ตุลาคม 2569 · **สถานะ:** LOCKED — ห้ามเปลี่ยนพฤติกรรมที่รับรองแล้วโดยพลการ  
**วัตถุประสงค์:** ให้เจ้าของระบบ ครู และ Codex เข้าใจตรงกัน ไม่สับสนระหว่างการเลื่อนเคอร์เซอร์ในตัวเลขกับการย้ายช่องคะแนน

## 1. แหล่งอ้างอิงที่มีอำนาจ

เอกสารนี้เป็นคำอธิบายใช้งานภาษาไทย **ไม่ได้แทนที่** แหล่งอ้างอิงเดิม:

1. ข้อวินิจฉัยพฤติกรรมที่เจ้าของผลิตภัณฑ์รับรองอย่างชัดแจ้ง
2. `2026-10-02-pp5-gradebook-behavior-registry.json` — **124 behaviors** ที่รับรองและมี test mapping
3. `2026-10-02-pp5-gradebook-spreadsheet-interaction-contract.md` — นิยาม state/focus/keyboard/clipboard/server
4. Golden Journeys **A–M** และ focused tests
5. Implementation ปัจจุบัน — ใช้เป็นหลักฐาน ไม่ใช่ตัวกำหนดกติกา

ถ้าคำอธิบายสั้น ๆ ในเอกสารนี้คลาดเคลื่อน ให้ถือ registry และ interaction contract เดิมเป็นหลัก และให้ Codex หยุดถามเมื่อมีความขัดแย้ง ห้ามเดาพฤติกรรมใหม่

## 2. หลักใหญ่: Online first, Excel familiar

- คะแนนทุกค่า สิทธิ์ สถานะปีการศึกษา/รายวิชา validation และยอดรวมมี **เซิร์ฟเวอร์เป็นผู้ตัดสิน**
- ช่องว่าง (**NULL/ยังไม่กรอก**) แตกต่างจาก **0.00/กรอกศูนย์แล้ว** เสมอ
- เลือกหรือคัดลอกคะแนนได้ ไม่ได้แปลว่ามีสิทธิ์แก้ไขคะแนน
- ตารางใช้ Tabulator local ที่ตรึงรุ่นไว้; ห้ามเปิดฟีเจอร์ native ที่ขัดกับระบบ เช่น sort/reorder/drag fill/formulas/Undo/Redo โดยไม่อนุมัติ
- ห้ามแสดงความสำเร็จของการบันทึกจากค่า optimistic ที่เซิร์ฟเวอร์ยังไม่ยืนยัน

## 3. ตารางแยกโหมดที่ต้องจำให้แม่น

| สถานการณ์ | กดลูกศรซ้าย/ขวา | กดลูกศรขึ้น/ลง | ความหมาย |
| --- | --- | --- | --- |
| **คลิกครั้งเดียว** เลือกช่อง ยังไม่เปิด input | ย้าย **ช่องคะแนน** | ย้าย **แถวคะแนน** | Grid navigation |
| **พิมพ์ตัวเลขทันที** บนช่องที่เลือก | **บันทึกและย้ายช่อง** | **บันทึกและย้ายแถวที่เขียนได้** | Direct entry / replace |
| **ดับเบิลคลิก** ช่องที่เขียนได้ | เลื่อน **caret ในตัวเลขเดิม** | **บันทึกและย้ายแถวที่เขียนได้** | Explicit edit |
| กด **Enter** บนช่องที่เลือก | เลื่อน **caret ในตัวเลขเดิม** | **บันทึกและย้ายแถวที่เขียนได้** | Explicit edit |
| กด **F2** บนช่องที่เลือก | เลื่อน **caret ในตัวเลขเดิม** | **บันทึกและย้ายแถวที่เขียนได้** | Explicit edit |
| ช่อง **อ่านอย่างเดียว/ประวัติ** | ย้ายช่องได้เมื่ออยู่นอก editor | ย้ายแถวได้ | ห้ามเปิด editor เพื่อเขียน |

**ข้อที่เคยสับสน:** ดับเบิลคลิกแล้วกด ← / → **ต้องไม่ย้ายไปช่องคะแนนข้าง ๆ** แต่ให้ขยับตำแหน่งพิมพ์ใน input ที่เปิดค่าเดิมไว้; **ไม่มี POST** จากการกดสองปุ่มนี้ ถ้า input หาย โฟกัสย้ายช่อง หรือมีคำขอบันทึก ถือว่าผิดสัญญา

ตรงกันข้าม เมื่อคลิกช่องแล้วพิมพ์ `5` ทันที จากนั้นกด → ระบบต้อง commit ค่านั้นและไปช่องถัดไปตามข้อกำหนด นี่เป็นพฤติกรรมที่ตั้งใจให้ต่างกัน

## 4. กฎรายละเอียดของ editor

- **Direct entry**: อักขระตัวแรกแทนค่าเดิม และพิมพ์อักขระต่อใน input เดิมจนถึง commit/cancel
- **Explicit edit**: โหลดค่าเดิม เช่น `12.50` และวาง caret ที่ท้ายข้อความใน input เดิม
- Explicit edit: ← / → เป็นการเคลื่อน caret ตามธรรมชาติ ไม่มีเซฟ ไม่มี navigation และ input เดิมต้องยังโฟกัส
- Direct entry: ← / → / ↑ / ↓ commit และย้ายไปช่องคะแนนที่ **เขียนได้** ตามทิศทาง; เมื่อสุดขอบ ไม่ล้ำเข้า identity/summary
- Explicit edit: ↑ / ↓ commit และย้ายตามแถวที่เขียนได้; Enter/Shift+Enter ลง/ขึ้น; Tab/Shift+Tab ขวา/ซ้าย และ Tab ออกจากตารางได้เมื่อสุดขอบ
- โหมดแก้ไขทั้งสอง: Escape ยกเลิกโดยไม่ส่ง request คืนค่าก่อนแก้ และโฟกัสกลับช่อง; Backspace/Delete, การเลือกข้อความ, copy/paste เป็นการแก้ไขข้อความภายใน input
- ป้องกัน IME composition ไม่ให้กด Enter ระหว่างประกอบอักษรแล้ว commit ผิดเวลา
- การออกจาก input ตามธรรมชาติยังบันทึกแบบ single-cell ตามสัญญา โดยไม่มี duplicate commit

## 5. กฎการเลือกช่วง การคัดลอก และวาง

- คลิกครั้งเดียวเพื่อเลือกและโฟกัส; ลากหรือ Shift+Arrow เพื่อขยาย/หดกรอบเฉพาะเซลล์คะแนน
- ชื่อนักเรียน ประเภทแถว และคอลัมน์สรุปไม่เป็นส่วนหนึ่งของการเลือกช่วงปกติ
- **Anchor** = จุดเริ่มลาก; **extent** = ปลายลากปัจจุบัน; **active** = ช่องรับคำสั่ง; **top-left** = มุมซ้ายบนของสี่เหลี่ยมหลัง normalize; **editor focus** ไม่ใช่ grid focus
- หลังเลือกช่วง 3×3 แล้ว copy ต้องได้ TSV เฉพาะคะแนน ไม่รวมชื่อหรือยอดรวม; ค่าว่างเป็นช่อง TSV ว่าง ส่วน `0.00` ต้องคงอยู่
- การ paste ใช้ช่องเดียวหรือมุมซ้ายบนของกรอบที่เลือกเป็นจุดเริ่มต้น และต้องพอดีกับขนาดตารางคะแนน **ทั้งหมด**; ห้ามตัดข้อมูล/บันทึกบางส่วน
- Paste/Fill/Clear ในช่วง ใช้ atomic batch; Delete/Backspace **นอก editor** ล้างคะแนนช่วงที่เลือก รวมถึงกรณี 1×1
- ถ้าช่วงมีเซลล์อ่านอย่างเดียว/ประวัติ ให้ **ปฏิเสธการเขียนทั้งช่วง** แต่ยังคัดลอกได้
- เมื่อ batch สำเร็จ กรอบเลือกต้องคงตามสัญญา และ top-left กลับเป็น active/focus สำหรับพิมพ์ต่อ เมื่อ Gradebook ยังเป็นเจ้าของโฟกัส
- Escape นอก editor ล้าง **กรอบการเลือก** ไม่ได้ลบคะแนน; ช่อง active ยังใช้ลูกศรต่อได้

## 6. กฎการบันทึกและเหตุการณ์พร้อมกัน

- ใช้เฉพาะ single-score POST และ batch-score POST ที่มีอยู่แล้ว
- คำสั่งช่วงที่ถูกต้องระหว่าง single-save ยัง pending ต้องรอคิวแล้วทำ **เพียงหนึ่งครั้ง** เมื่อปลอดภัย (**GB-COMMAND-001**); ห้ามทิ้งคำสั่งให้ผู้ใช้ลองใหม่โดยไม่จำเป็น
- Batch ห้ามแข่งกับ single-save ที่ยังค้าง
- ถ้า permission หาย, ผลการบันทึกไม่แน่นอน, 409, network timeout หรือ response สำเร็จแต่ข้อมูลยืนยันผิดรูปแบบ ต้องล็อก **การเขียนเพิ่มเติม** จนผู้ใช้โหลดใหม่เพื่อตรวจสอบ; ห้าม retry อัตโนมัติ
- Late response ห้ามดึง focus กลับช่องเก่า ทับข้อความที่ใหม่กว่า หรือดึง scroll กลับ
- เซิร์ฟเวอร์กำหนดค่าคะแนนที่บันทึกจริงและยอดรวม; การเปลี่ยน `5` เป็น `5.00` หลังยืนยันต้องไม่กระตุก/กระโดด
- Invalid single score ต้องยังแสดงข้อความที่ลองกรอกกับข้อผิดพลาด โดยยอดรวมจากเซิร์ฟเวอร์ยังไม่เปลี่ยนและแก้ไขต่อได้

## 7. กฎความนิ่งของจอและความสามารถใช้งาน

- ย้ายไปช่องที่เห็นครบแล้ว: ห้าม document scroll / Tabulator holder scroll เปลี่ยนอย่างไม่จำเป็น
- ช่องที่อยู่นอก viewport: เลื่อนเฉพาะ holder เท่าที่จำเป็น รวมพื้นที่ frozen identity
- ห้ามเปลี่ยนความสูงแถว ความกว้างคอลัมน์ ขอบ input สองชั้น หรือทำ grid กระโดดเพราะ focus/status
- เมื่อตารางยังเป็นเจ้าของ focus การนำทางต้องโฟกัสช่องเป้าหมายทันที แม้ request ช่องก่อนหน้าจะตอบช้า
- เปลี่ยน UI รอบตารางได้ แต่ห้ามรบกวน Grid DOM, keyboard, clipboard, selection, editor, layout และ score serialization
- คู่มือ/คำอธิบายที่ไม่จำเป็นควรถูกซ่อนไว้ใน help disclosure เพื่อให้พื้นที่ตารางเป็นหลัก; **ต้องคงคำแนะนำและความหมายด้าน accessibility ที่จำเป็นไว้** และไม่เปลี่ยนพฤติกรรมกริดเพราะปรับ UI

## 8. ขั้นตอนเมื่อมีรายงานว่า Gradebook ผิดปกติ

1. หยุดการสรุปว่า release interaction gate ผ่านจนกว่าจะตรวจ
2. ระบุให้ชัดว่าผู้ใช้หมายถึง **caret ภายในตัวเลข** หรือ **ช่องคะแนนข้างเคียง** และเริ่มจาก single click / typing / double-click / Enter / F2
3. ทำซ้ำด้วยการกดจริงใน Chrome และถ้าปลอดภัยให้ตรวจ authenticated MAMP; แยก synthetic / trusted fixture / MAMP
4. บันทึกก่อน-หลัง: active cell, same input identity, `document.activeElement`, `selectionStart/End`, POST count, grid range, document/holder scroll
5. ถ้าทำซ้ำไม่ได้ **อย่าแก้โค้ดแบบคาดเดา**; บันทึกข้อจำกัดและขอหลักฐานเพิ่ม
6. ถ้าทำซ้ำได้ แก้เฉพาะ root cause; เพิ่ม test ที่ fail ก่อน fix และ pass หลัง fix โดยไม่เปลี่ยนข้อกำหนดเพื่อหลบ regression

### ประวัติกรณีสับสน ตุลาคม 2569

ผู้ใช้รายงานว่า double-click แล้ว ←/→ "ย้ายช่อง" แต่การตรวจ Task 5R ที่รายงานจาก Codex **ยังไม่สามารถ reproduce ได้**: desktop fixture และ authenticated MAMP พบว่า caret เคลื่อนภายใน input เดิม ไม่มี POST; Registry 124, direct-entry 54 และ PHPUnit 3,092 tests ผ่าน ขณะที่ mobile/native-browser และ browser gates ทั้งหมดยังตรวจไม่ครบ

**สถานะของกรณีนี้คือ UNCONFIRMED ไม่ใช่ FIXED หรือ REPRODUCED** และยังไม่มีเหตุให้เปลี่ยนพฤติกรรมที่รับรองแล้ว

## 9. Release gate ที่ห้ามข้าม

สำหรับการเปลี่ยนแปลงที่กระทบ Gradebook โดยตรง **หรือกระทบทางอ้อมผ่าน shared styles/layout/events/assets** ต้อง:

- ผ่าน validator ของ registry **124 ID และ mapping เดิม** (`php tests/Browser/gradebook-behavior-registry-check.php`)
- ผ่าน Golden Journeys **A–M (13 journeys)** ด้วย pointer, keyboard และ clipboard ที่เกิดจากเบราว์เซอร์จริง
- ผ่าน focused suites: direct-entry, explicit editor, selection/range, clipboard, errors, races, parity, layout, visual-stability, workload, historical/read-only
- ผ่าน focused และ full PHPUnit, PHP/JS syntax, `git diff --check`
- ตรวจ MAMP แบบ authenticated เมื่อมี session ปลอดภัย; **ห้ามใช้คะแนนจริงเป็น fixture ที่แก้ไขได้**
- แยกหลักฐานอย่างเคร่งครัด: registry เป็นการตรวจ mapping ไม่ใช่การพิสูจน์ UX; synthetic ไม่ใช่ trusted browser; fixture ไม่ใช่ authenticated MAMP
- ไม่ผ่าน/ยังไม่รัน/ถูกบล็อก = **ห้ามรายงานว่า interaction release gate ผ่าน**
- Product-owner visual และ spreadsheet-feel acceptance เป็นอีก gate ที่ test ผ่านแทนไม่ได้

## 10. การขอเปลี่ยนกฎ

พฤติกรรม 124 รายการและ contract เดิมมีสถานะ **LOCKED**. ไม่อนุญาตให้ Codex แก้โดยอ้างว่า "สะดวกกว่า", "Tabulator ทำแบบนี้", "test เดิมผ่าน", หรือ "โค้ดปัจจุบันทำแบบนี้"

การเปลี่ยนข้อใดต้อง:

1. ระบุ behavior ID และ old/new behavior
2. รับการตัดสินใจ/อนุมัติอย่างชัดเจนจากเจ้าของผลิตภัณฑ์ก่อน
3. แก้ interaction contract + registry entry/mapping + golden/focused tests + corrective history **ใน commit เดียวกัน**
4. รัน release gate ทั้งหมดและรายงานหลักฐานจริง
5. หาก gate ไม่ครบ ให้คงสถานะ pending และไม่สรุปว่า accepted

**ข้อจำกัดของคำว่า LOCK:** เป็น policy/review lock ใน repository ซึ่ง agent ต้องปฏิบัติตาม ไม่ใช่ branch protection หรือการบังคับ GitHub CI อัตโนมัติ การป้องกันระดับระบบต้องตั้ง required checks/branch protection เพิ่มภายหลัง
