## Architecture

`GET /workspaces/classrooms/{classroomId}/students` is a protected SCHOOL route requiring `STUDENT_VIEW`. `ClassroomRosterReadService` independently checks that live permission before reading students, then resolves the classroom through `ClassroomWorkspaceReadService` under the authenticated school. Browser school/year/grade/classroom query fields cannot replace authoritative context. Foreign, inaccessible, malformed and missing classrooms fail with safe 404 responses; unauthenticated requests retain the login redirect.

The new read model reuses `StudentEnrollmentRepository::listForSchoolYear` with authoritative year, grade, classroom and `ACTIVE` enrollment filters. The existing query already joins students and years by school, and placements/classrooms by school, year and grade. It does not select national ID or birth date. No new repository SQL was needed. Only student/enrollment locators, student code, display name and enrollment status enter the roster row projection.

There is one roster query, with no query per student. Existing workspace navigation retains its existing Gradebook authorization projection; no scores or components are read. A 12-student growth test proves the total request query count remains constant.

The controller renders the new students view through `View::page` and the existing workspace shell/global layout. The local นักเรียน item links to the real route and has `aria-current="page"`. Switching still navigates to the chosen classroom's overview, with no stored selection or speculative persistence. Subject/teaching navigation retains Task 2's separate year-wide legacy destinations.

## Inclusion and exclusion contracts

- Include enrollment `ACTIVE` plus an `ACTIVE` placement in this exact school/year/grade/classroom, ordered by existing student-code ordering.
- Exclude ended placements, unplaced enrollments, students now in another classroom, other years/schools, and terminal enrollments. Explicit tests also exclude terminal enrollments with a lingering ACTIVE placement.
- Existing fixtures include historical status spellings; Task 3 does not translate or rewrite persisted status values.
- A move ends the old placement (`ENDED`, `ended_at`) and inserts a new ACTIVE placement. Returning to an earlier room creates another row; old rows remain.
- `TRANSFERRED_OUT` / `WITHDRAWN` end the current placement. Existing services forbid reactivation or switching terminal types. No terminal record is rewritten by roster reads.
- CLOSED years remain readable when authorized, showing the placements still active in that selected year. They have no roster mutation/add/import entry controls.
- An INACTIVE student master does not erase an ACTIVE enrollment/placement in a historical year. Existing master inactivation rules reject active enrollment in an open year; the roster does not invent an additional master-status filter.
- An INACTIVE classroom does not erase existing placements. In an open year a manager may still move students out or change their status through existing services. Add/import entry links are hidden for that room.
- A zero-row classroom is a normal page with a teacher-oriented empty message. The displayed count is exactly the authorized projected row count.

The domains remain distinct: **student master → yearly enrollment → classroom placement history**. Task 3 adds no mutable roster entity and never updates student master or score rows as a room-move shortcut.

## Contextual actions and existing write behavior

The roster exposes permission-checked entry links to existing full-page forms, not new write endpoints:

- ดูข้อมูลนักเรียน → existing student detail with its existing masked-ID/history behavior.
- ย้ายห้อง → `/academic/enrollments/{id}/edit#move-classroom`.
- ย้ายออก / ลาออก → `/academic/enrollments/{id}/edit#student-status`.
- เพิ่มนักเรียนเข้าปีการศึกษานี้ → existing enrollment-create form, with authoritative year/grade defaults; the user chooses the student and classroom there.
- นำเข้านักเรียนจาก CSV → existing import workflow, guarded by `STUDENT_IMPORT`; year and CSV classroom mapping are verified in that workflow. No automatic classroom filter/prefill is implied.
- รายการนักเรียนและตัวกรองเพิ่มเติม → legacy filtered enrollment list, retaining the revalidated workspace locator.

Two section anchors are the only change to the existing enrollment form. Full-page mutation forms and redirects keep their existing behavior. These entry links do not carry a trusted source room or return URL, and do not add a second mutation implementation. On opening the form the existing controller resolves the enrollment's current student, year, grade, classroom and history. POSTs operate on that authoritative enrollment under the existing permission middleware and domain service locks, even after a stale roster was opened.

`ENROLLMENT_MANAGE` controls move/status/create links; `STUDENT_VIEW` alone never provides them. `STUDENT_IMPORT` is checked separately. Gradebook-only users receive neither roster access nor a roster link/count; direct access fails before student queries. Individual grants and live revocations are tested without changing role names or adding permission codes.

All move/status writes retain the existing POST+CSRF routes, SchoolContext, tenant checks, exact permission checks, target classroom school/year/grade/ACTIVE validation, DRAFT/ACTIVE-year checks and enrollment lifecycle rules. `EnrollmentAdministrationService` remains the only mutation implementation. Its original transaction includes enrollment, placement and audit operations. Failure injection after earlier writes proves full rollback with no partial placement, enrollment, audit, student-master or score changes. Existing broader tests also cover begin/commit failures and stale revalidation.

Existing audit actions remain `STUDENT_CLASSROOM_PLACEMENT_CHANGED` and `STUDENT_ENROLLMENT_STATUS_CHANGED`. Focused HTTP tests verify actor, school, entity/action, before/after metadata, IP and timestamp. No second audit path was added. Legacy direct routes and import Upload → Preview → Apply/Cancel behavior are unchanged.

## Privacy, accessibility and responsive behavior

No national ID, birth date, gender, profile attributes or placement history is loaded into the roster model. Display values and accessible link names are escaped. No profile data is put in hidden fields or data attributes. Raw technical IDs occur only as legitimate URL locators. No classroom roll number is invented; the existing student code is shown.

The dense semantic table has a caption, column headers, name row headers, Thai textual status, contextual accessible action labels, and the existing named/focusable internal table-scroll region. The shared focus styles, switcher and logout POST+CSRF form remain intact. No production CSS or JavaScript changes or dialogs were needed. Synthetic browser cases include hostile long names and ordinary/empty/read-only rosters at 1440×900, 1024×768, 768×1024 and 390×844. Checks cover document overflow, scrolling action reachability, visible/unoccluded focus, active navigation and switcher access. Native Enter/Space switcher activation was also exercised.
