## Interaction contract

Task 6 keeps its single `activeKey` (`offeringId-componentId-enrollmentId`), focus revision, composition guard, vertical navigation, blur-only save, HTMX table queue, success header, typed-error retention, and stale-response focus protection. Task 7 separately holds `selectionAnchor` and `selectionExtent` as integer score-row/score-column coordinates. The normalized inclusive rectangle derives from these points. Selection never grants editability and does not change Task 6's active key. A focused editable cell can remain inside a selected range.

The server-rendered score `<td>` carries row/column coordinates, component/enrollment IDs, and an informational editable flag. The row order is the authorized rendered Gradebook row order; columns are rendered score components only. These stable TDs remain in place when HTMX replaces an inner score fragment. Student identity, row type, totals, completeness, and teacher metadata have no score-cell marker. A one-time topology map indexes the TDs by coordinate; Task 7 does not dynamically add/remove rows or components. Task 8 must reassess this assumption if it changes the page topology. The Task 6 navigation index continues to contain only writable current-row inputs; historical and read-only cells cannot become keyboard edit destinations.

Primary desktop mouse/pen pointer down on score-cell padding or read-only display starts a new range and replaces the old one. Pointer activity inside an editable input stays native for caret/text selection. Pointer move uses the cell at the current pointer location and normalizes the rectangle in every direction. Pointer up ends and announces the range. Pointer cancel, a lost mouse button, or window blur clears the transient range so selection mode cannot stay stuck. Right/auxiliary and touch pointers do nothing. There is no pointer capture, global `user-select` override, drag auto-scroll, or touch scroll interception. Dragging across a larger grid requires the user to scroll and start another range; this is a known Task 7 limitation.

With an editable input focused, Shift+Up/Down creates or changes a vertical range: the first press anchors at the active cell, subsequent presses move the extent while leaving the anchor fixed, and movement stops at rendered row boundaries. Historical rows may be included for copy. Shift+Left/Right retain native text selection; there is no horizontal keyboard range extension. Enter and Shift+Enter preserve Task 6 next/previous editable current-row behavior. Plain Up/Down preserve Task 6 navigation, Left/Right preserve caret movement, Tab/Shift+Tab remain native, and IME/composition and unrelated modifiers are guarded. Plain Task 6 vertical navigation and Enter clear an existing range. Escape clears only the range; it neither modifies a score nor posts. Focusing outside the Gradebook clears the range. Pointer selection does not blur an input directly; a later ordinary focus/blur may still trigger Task 6's save.

Selected TDs receive a tinted background, dashed inset outline, and solid perimeter edges. Task 6's active/focus outline stays on the inner score fragment, distinct from the wider range. Historical rows retain textual read-only wording and their existing background. The semantic table and native inputs remain. A polite status region announces only completed pointer ranges, keyboard steps, clears, and successful copy; pointer moves are silent. No screen-reader certification is claimed.

## Clipboard and authority boundary

The document `copy` event writes only `text/plain` when a score range exists and clipboardData accepts the value. Ctrl+C and Cmd+C use the same browser event. A non-collapsed selection in the focused score input has native-copy precedence; non-collapsed page text selected outside the Gradebook also remains native. Missing clipboardData causes no exception or false success. Copy does not blur, request data, POST, normalize, or update totals.

TSV uses tabs between every selected column and `\n` between rows, retaining interior and trailing empty fields. Values are read from the current visible input at copy time, including dirty, saving, retryable, and error text; read-only values come from the visible server-rendered score span. Blank is empty and explicit `0.00` remains nonempty. Historical values are eligible only because they are already visible on the authorized page; they remain non-input cells. Identity metadata and component headers are intentionally excluded. No hidden personal data is added to the DOM or clipboard. Selection attributes are presentation metadata, never future write authorization; Task 8 must authorize and validate every target server-side.
